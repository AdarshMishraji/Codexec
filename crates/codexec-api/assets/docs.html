codexec API

A REST API for submitting source code to an isolated, resource-limited sandbox (CPU time, CPU rate, and memory are all independently enforced) and retrieving the result. Every request and response body is JSON.

Base URL __ORIGIN__
← Live dashboard Admin Portal (manage plugins & keys) Playground (try requests live) →

Authentication

Every non-public endpoint uses the same scheme — an Authorization: Bearer <token> header — but there are two independent tokens, and they are not interchangeable.

SchemeHeaderProtectsHow to obtain it
API key Authorization: Bearer cxk_… All /submissions routes Admin Portal → API Keys tab → Create Key (or POST /admin/api-keys below). Shown once at creation — only its hash is stored server-side, so a lost key can't be recovered, only revoked and replaced.
Admin token Authorization: Bearer <token> All /admin/* routes A single static value set by whoever deploys codexec, via the ADMIN_API_TOKEN environment variable. Not created or rotated through the API.
Public, no auth required: GET /, GET /admin, GET /docs, GET /stats, and GET /languages. Everything else requires one of the two tokens above.
Body requests need a real Content-Type. Every POST below expects Content-Type: application/json. Omit it and you get a framework-level 415 with a plain-text body (Expected request with `Content-Type: application/json`) — not the JSON error envelope described below. Malformed JSON similarly returns a plain-text 400 (e.g. Failed to parse the request body as JSON: key must be a string at line 1 column 2). Both are framework-level responses, verified against the live server, not the {"error", "message"} shape used everywhere else in this document.

Errors

Outside the Content-Type/malformed-JSON edge case above, every error response (any status ≥ 400) uses the same envelope:

{
  "error": "unknown_language",
  "message": "No active plugin registered for language 'cobol'"
}

error is a stable machine-readable code — safe to switch on in client code. message is a human-readable detail that may change wording over time.

errorStatusMeaning
unknown_language422The language slug doesn't exist, or exists but is deactivated. Both cases look identical to the caller by design.
invalid_cpu_time_limit422cpu_time_limit_ms is ≤ 0 or exceeds the effective ceiling for this language.
invalid_cpu_limit_cores422cpu_limit_cores is ≤ 0 or exceeds the effective ceiling for this language.
invalid_memory_limit422memory_limit_kb is ≤ 0 or exceeds the effective ceiling for this language.
source_too_large422source_code is empty, or it (or expected_output) exceeds MAX_SOURCE_CODE_BYTES (default 65536 bytes).
invalid_label422An API key's label was empty or all whitespace.
invalid_api_key401Missing, unrecognized, or revoked API key on a /submissions route.
unauthorized401Missing or incorrect admin token on an /admin/* route.
not_found404No resource exists at the given id/slug.
conflict409The request is well-formed but can't be applied right now — currently only returned when deleting a plugin that has submission history.
queue_unavailable503The submission couldn't be published to the execution queue; nothing was persisted — safe to retry.
internal_error500An unexpected server-side failure (e.g. a database error).

Submissions

The core of the API: submit source code for execution, then poll for the result. Submitting is asynchronous — there is no synchronous "run and wait" mode — so a typical integration submits once and polls GET /submissions/{id} every second or so until the status is terminal.

POST/submissions

Queues a new submission for execution and returns immediately.

Requires API key

Request body

FieldTypeRequiredDescription
languagestringrequiredAn active language's slug (see GET /languages).
source_codestringrequiredNon-empty, up to MAX_SOURCE_CODE_BYTES (default 65536 bytes).
stdinstringoptionalDefaults to "". Piped to the program's standard input.
expected_outputstring | nulloptionalWhen set, enables grading: verdict becomes "accepted" or "wrong_answer" once the run completes (exact match after trimming trailing whitespace per line and trailing blank lines). Left null, the submission is execution-only and verdict stays null forever.
cpu_time_limit_msinteger | nulloptionalDefaults to the language's default_cpu_time_limit_ms. Must be in (0, effective_max], where the effective max is min(language.max_cpu_time_limit_ms, platform ceiling).
cpu_limit_coresnumber | nulloptionalDefaults to the language's default_cpu_limit_cores. Same ceiling rule as above, against max_cpu_limit_cores.
memory_limit_kbinteger | nulloptionalDefaults to the language's default_memory_limit_kb. Same ceiling rule as above, against max_memory_limit_kb.
Two independent CPU controls. cpu_limit_cores is a hard rate cap (kernel-enforced via the cgroup's CFS quota — e.g. 1.5 cores throttles concurrent CPU draw). cpu_time_limit_ms is a total CPU-time budget the worker enforces by polling cumulative usage and killing the process once it's exceeded. A program can hit either independently of the other.

Example request

curl -X POST __ORIGIN__/submissions \
  -H "Authorization: Bearer cxk_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "language": "python3",
    "source_code": "print(\"hello, world\")",
    "stdin": "",
    "expected_output": null,
    "cpu_time_limit_ms": 2000,
    "cpu_limit_cores": 1.0,
    "memory_limit_kb": 262144
  }'
202Accepted — queued
{
  "id": "3583fc02-4500-45e7-9eaf-1455fe7fc9fb",
  "status": "queued",
  "submitted_at": "2026-09-12T07:28:10.806118Z"
}
401invalid_api_key — missing, unknown, or revoked key
422unknown_language / invalid_cpu_time_limit / invalid_cpu_limit_cores / invalid_memory_limit / source_too_large
503queue_unavailable — nothing was persisted; safe to retry

Response fields

FieldTypeDescription
statusenumOne of queued, processing, completed, compile_error, runtime_error, time_limit_exceeded, memory_limit_exceeded, internal_error. Anything other than queued/processing is terminal.

stderrstring | nullCaptured standard error.

exit_codeinteger | nullThe program's process exit code, once it has run.
cpu_time_used_msnumber | nullActual cumulative CPU time consumed, read from the cgroup — not wall-clock time.
memory_used_kbinteger | nullPeak resident memory, read from the cgroup.
error_messagestring | nullSet only when status = internal_error — details of the platform-side failure.

Languages

Public, read-only. Lists every currently-active plugin along with the limits your submissions to it are validated against.

GET/languages

Active languages only — inactive/unregistered ones never appear here, and behave identically to an unknown slug from POST /submissions' point of view.

Public

Example request

curl __ORIGIN__/languages
200OK — array, one entry per active language
[

Note what's not here: image_ref, compile_cmd, and run_cmd are internal implementation details, only exposed via the authenticated admin listing.

Admin API

Everything under /admin requires the admin bearer token (see Authentication) and is meant for operators managing the platform — registering plugins and issuing API keys — rather than end-user integrations. The Admin Portal is a full UI over this same API, including a Playground for live testing.
